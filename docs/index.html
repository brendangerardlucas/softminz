What SoftMinZ measures

SoftMinZ uses seven separately standardized components from six benchmarks in the Artificial Analysis Intelligence Index v5.0, selected for scientific computing:

  • Terminal-Bench 4.0
  • FrontierCode 2.0
  • AA-Omniscience v1.1 — Accuracy
  • AA-Omniscience v1.1 — Non-hallucination
  • HLE-Diamond
  • CritPt v2 (Hard Subset)
  • Terminal-Bench-Science 0.1

Terminal-Bench 4.0 measures general terminal execution; FrontierCode 2.0 tests changes to real software repositories; Terminal-Bench-Science 0.1 covers scientific terminal workflows. CritPt v2's hard subset and HLE-Diamond test difficult scientific reasoning and knowledge. AA-Omniscience v1.1 contributes two distinct inputs: accuracy and non-hallucination rate (1 minus AA’s hallucination rate). Each gets its own cohort mean, sample standard deviation and z-score.

The combined Omniscience Index is not scored. Accuracy and non-hallucination each enter the partition sum once, alongside the five other components. The former SciCode, AA-LCR, original HLE and original CritPt measurements are not used. FrontierCode 1.x, full CritPt v2 and AA-Omniscience v1 cannot substitute for the named versions or hard subset. Versions are not treated as interchangeable.

Complete cohort, sample z-scores

A model must have a finite score on all seven components to receive SoftMinZ or contribute to any component's normalization. Partial profiles are excluded from both the ranking and all z-score pools. Every component uses the same complete cohort of 76 models, with its mean and sample standard deviation:

zb = (xb − μb) / sb   ;   sb uses the n − 1 denominator
Z = Σi=1…7 exp(−zi)
SoftMinZ = −ln(Z / 7)

The partition function is divided by seven to take the mean of the Boltzmann factors, not a linear average of the z-scores. AA's Intelligence Index weights do not weight the performance score. A component's local influence is exp(−zi) / Z, so weaker components matter more; there are no fixed 1/7 linear score weights. The soft-minimum lies between a model's worst and mean z-score. Weak dimensions receive more influence: balanced excellence is rewarded, while strength on one benchmark cannot linearly cancel weakness on another.

The battery, evaluation versions and cohort changed with AA v5.0. These values and rankings are not directly comparable with either the former pre-v5 battery or the initial six-component v5 score that used the combined Omniscience Index. Missing data is never filled with older benchmark versions.

Cost per expensive agentic task

The cost axis is a separate workload selection from the science performance battery. We retain the original technique: read AA's published weighted per-benchmark cost per task, divide by that benchmark's current Intelligence Index weight, and average the unweighted costs using task counts.

The four selected workloads are AA-Briefcase v1.1, Terminal-Bench 4.0, FrontierCode 2.0 and Terminal-Bench-Science 0.1. They are the clear high-cost, long-running agentic-workload group in the v5 published data. This is a fixed set for every model, not a model-specific choice of whichever measurements look favorable.

Today's denominator is 359 tasks across those four workloads. Task counts and weights are parsed from AA's live methodology table. Repeats are not multiplied into the task counts: the input is AA's published per-task cost, not the cost of our rerunning its evaluations.

AA-Omniscience v1.1 and HLE-Diamond have many cheap questions and do not enter the cost average. GDP.pdf, AutomationBench-AA and CritPt v2 (Hard Subset) are also excluded from this cost subset because their typical published per-task costs are substantially lower than the four selected workloads. A benchmark can be included in performance without being included in cost, and vice versa. GDPval-AA and AA-LCR are no longer members of the v5 Intelligence Index and supply no cost weights here.

All nine current Intelligence Index cost components, including the excluded cheap ones, must be present in a cost split and must sum to AA's published total before the four-workload cost is accepted. Costs are never inferred from token prices, a related model or another reasoning level. Only 71 of 76 scored models have a complete positive published cost today; the remainder show — and are excluded from the log-cost chart and Pareto frontier, not treated as free. Source-zero prices are also excluded rather than promoted as zero-cost winners. A zero in one published component is retained if the complete four-workload average is positive. AA’s reported costs retain its published cache-hit and pricing assumptions; they are not cache-free estimates.

Reproducibility

Scraped scores are cross-checked against overlapping scores on each evaluation page, using JSON-LD score rows when available and the evaluation-page model payload otherwise. A benchmark whose parsed values disagree is rejected rather than published; missing comparison data is reported as unavailable, never as validated, and aborts generation. Intelligence Index weights and task counts used in the cost model are parsed live from the AA methodology page on every run (today: live (AA v5.0 methodology page, parsed this run)); if that page is unreachable or its table cannot be parsed, the run aborts rather than publish costs computed from stale weights.
